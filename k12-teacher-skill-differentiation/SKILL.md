# 中国 K-12 差异化教学

把已有课例改造成可在中国班级授课条件下实施的差异化方案。保持同一课程标准、单元目标、核心情境和认知挑战，只调整进入路径、支架强度、表达方式和拓展深度。

## 0. 路由并读取参考

1. 识别小学、初中、普通高中或五四学制。
2. 识别学科。
3. 必须读取：
   - `references/curriculum-grounding.md`
   - `references/differentiation-principles.md`
   - `references/subject-routes.md`
4. 不使用美国州标准、CCSS、NGSS、ELA、Social Studies、IM、OSE 或 Learning Commons KG。
5. 识别教材版本、册次、单元和课题；未确认时不得猜测。

### 交互式提问协议

需要教师补充、确认或选择时，使用宿主提供的结构化用户输入工具（如 `request_user_input`、`AskUserQuestion` 或等价能力），不要直接发送开放式问题：

- 一次交互最多呈现 2 个问题，每个问题提供 2–3 个互斥选项；
- 把推荐项放在第一位，并用一句话说明选择的影响；
- 原课目标、具体学情等无法穷举的信息，使用交互组件的“其他/自行输入”入口；
- 能从上传材料或上下文提取的信息不重复询问；
- 需要文件时提供“现在上传”“使用前文课例”“按课题和核心目标建立最小源课”等可执行选项；
- 宿主确实没有结构化输入能力时，才退化为单条 A/B/C 选项消息，不得改成连续开放式提问，并说明当前界面不支持点击选择。

## 1. 取得并理解源课例

按顺序判断：

- 前文已有课例：直接使用，不重复索要；
- 教师上传文件或图片：完整读取，提取学段、学科、教材、目标、任务、评价和作业；
- 教师提供链接：读取可访问内容；失败时请其上传或粘贴；
- 教师只给教材位置：取得版本、册次、单元、课题和本课目标后继续；
- 没有源课例：使用交互式选择提供“上传/粘贴已有课例（推荐）”“切换到 `china-k12-lesson-planning` 从零设计”“按课题和核心目标建立最小可行源课”。

若教师只提供“课题 + 核心目标”，但明确这就是全部可用信息，可据此建立一个最小可行源课：保留其目标，补写原创核心任务和课堂检测，并把教材位置、课时和学情假设标为待核对。只有连核心目标或教学内容都无法判断时才停止。不得根据一个课题名称伪造“原教案”。先概括原课的核心目标、核心任务和课堂检测，再使用交互式选择提供“确认并继续（推荐）”“调整概括”“改为从零设计”。

## 2. 识别学情，不用静态标签

优先使用教师提供的证据：

- 课堂观察、作业样本、单元检测或前测；
- 学生在哪个步骤出错；
- 概念理解、程序熟练、阅读理解、表达、注意/执行功能或语言方面的具体需要；
- 随班就读学生的合理便利和教师可公开使用的支持信息；
- 学有余力学生已经达到的表现。

不要索取姓名、诊断报告全文或无关隐私。没有数据时使用“暂定学习起点”，并明确需要根据本课形成性评价调整。

学生材料只使用 Group A / Group B / Group C 或教师指定的中性名称。不得出现“差生”“学困组”“低层”“简单版”“培优组”等标签。

## 3. 建立中国课程依据

沿用源课例的现行课程标准与教材位置。按 `references/curriculum-grounding.md` 核对：

- 义务教育：《义务教育课程方案和课程标准（2022年版）》；
- 普通高中：《普通高中课程方案和语文等学科课程标准（2017年版2020年修订）》；
- 教材以教师实际版本为准。

中国课程标准没有统一细粒度代码时，不编造代码。记录学段、核心素养、课程内容主题/任务群、学业要求和教材单元。无法核实的逐字表述改为“依据课标概括，待教师核对”。

## 4. 执行八条差异化规则

1. **一套教师方案，三份纯学生任务单。** 不生成三份混有教师说明的“不同难度教案”。
2. **目标与核心素养不降级。** 三组处理同一核心目标和关键难点；A 组获得通向目标的支架，不删掉最重要的思维。
3. **从真实学习障碍出发。** 先判断卡点是先备概念、阅读、语言表达、表征、程序、证据使用还是执行功能，再选支架。
4. **支架不代替思考。** 每个任务最多 1–2 个嵌入式支架；不给答案暗示、关键词捷径或只剩填空的模板。
5. **具备形成性评价基础设施。** 包含具体检查点、分组依据、可调整规则、各组教师追问、共同的早完成任务和反思任务。
6. **调整保持隐形。** 相同情境、文本/材料和核心任务优先；学生页不解释谁“低于”或“高于”。
7. **支架逐步撤除，拓展增加新思维。** A 组按强支架 → 轻支架 → 独立迁移；C 组做概括、评价、设计、反证、多情境迁移或更高阶连接，不是多做几题。
8. **分组灵活且可执行。** 分组依据来自本课证据，课中可以调整；设计适配 40 人以上班级，减少教师同时管理的材料和口令负担。

## 5. 先做双向一致性检查

渲染前逐项检查：

- 教师方案列出的每个学生任务，在至少一份任务单中真实存在；
- 每份任务单的任务、拓展、课堂检测、早完成任务和反思，都在教师方案中列出；
- 三组共享任务使用同一 `shared` 键，不重新改写；
- 课程标准和教材位置在四份材料中一致；
- A 组仍完成核心任务，C 组拓展能说清“新增了什么思维”；
- 作答空间、材料、时间和教师巡视量适合真实班级。

## 6. 生成四份材料

读取 `references/document-schema.md`。创建 `differentiation.json`：

- `shared`：课程身份、课标依据、教材位置、核心任务、课堂检测、词汇/概念工具、共同早完成任务和反思；
- `teacher_plan`：教师差异化方案；
- `worksheet_group_a`：起点支持较多；
- `worksheet_group_b`：按目标要求独立完成；
- `worksheet_group_c`：深化或迁移；
- 三份学生材料只在支架和拓展 block 上不同，核心任务全部从 `shared` 拉取。

教师方案至少包含：

1. 原课目标与不可降低项；
2. 学情证据与暂定分组；
3. 三组任务、支架、教师追问和预期表现对照表；
4. 课中形成性检查与换组规则；
5. 共同课堂检测及分流后的下一步；
6. 设计理由；
7. 大班实施说明。

先运行结构验证：

```bash
python scripts/validate_material_source.py differentiation.json --mode differentiation
```

通过后运行：

```bash
bash scripts/render_all.sh differentiation.json "$OUTPUT_DIR"
```

无 Bash 的 Windows 环境：

```powershell
python scripts/render_documents.py differentiation.json --format both --outdir <输出目录>
```

确认四个 ID 均有 `.docx` 与 `.html`。

## 7. 交付与修订

交付时向教师说明：

- Group A/B/C 只是本课暂定学习路径，不是固定能力等级；
- 分组依据是什么，何时调整；
- 未提供具体学情时采用了哪些通用支持；
- 课程依据和教材位置哪些已核实、哪些待核对；
- 使用交互式选择收集反馈，提供“满意并结束”和 2–3 个课例相关调整选项，不直接开放式追问。

材料交付后，读取 `references/narrativeos-case-guidance.md`，按本课目标提供可选的 NarrativeOS 案例引导。

修订时改 `differentiation.json` 后重渲染四份文档。共享内容只在 `shared` 修改；单组支架只改该任务单。不得直接改 Word。

## 版权、隐私与公平

- 原创编写任务，不复制教材、教参或试卷的大段内容。
- 不把残障、家庭背景、语言、地区或考试成绩当作能力定论。
- 合理便利可以改变呈现与作答方式，但不能无依据地降低课程目标。
- 不在学生材料中出现诊断、IEP、随班就读或成绩分层信息。
